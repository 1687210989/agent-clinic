## 指标明细

### E1 死循环 〔高〕

| 项 | 内容 |
|---|---|
| 数据来源 | `tool/call` + `tool/result` |
| 判定 | 同 `tool_name` + 同 `tool_args_hash` 复现，且配对结果**均为错误** |
| 阈值 | ≥3 次 |
| 防误报 | **参数有变化的试错不计入**（哈希不同即不算） |
| 实测 | 本机数据中**未命中**（0 例）—— 详见下方校准记录 |

### E2 反复失败 〔中〕

| 项 | 内容 |
|---|---|
| 数据来源 | `tool/result` 的 `is_error` |
| 判定 | 会话工具错误率 = 错误数 / 工具调用数 |
| 阈值 | >30% |
| 前置条件 | 该会话工具调用数 ≥10（样本太小不下结论） |
| 实测基线 | 各会话 0% / 7.7% / 9.6% / 10.8% → **未命中**，符合预期 |

### E5 冗余重复调用 〔中〕（**实测新增**）

| 项 | 内容 |
|---|---|
| 数据来源 | `tool/call` + `tool/result` |
| 判定 | 同 `tool_name` + 同 `tool_args_hash` 重复 ≥3 次，且配对结果**均无错误** |
| 与 E1 的边界 | E1 = 同参数 + **同错误**（卡死）；E5 = 同参数 + **无错误**（冗余） |
| 防重复报 | 只要有一次错误，就交给 E1，E5 不报 |
| 实测 | **命中 1 例**：`list_agents` 同参数成功调用 4 次（可省 3 次） |

**为什么新增 E5**：

任务书的 E1 要求「同参数 **+ 同错误**」，但实测本机数据里同参数重复 4 次的
`list_agents` 调用**全部成功** —— 严格按 E1 定义一条都命中不了。
而这类「同参数、成功、重复」的调用同样在浪费 token（每次调用都要重新
走一遍模型 + 工具），属于真实的成本浪费，值得单独报出。

这是**用真实数据校准指标**的结果，不是凭空调参。

### C1 token 消耗过快 〔高〕（M2）

单会话 `output_tokens` 及日均值 vs **自身** 30 天中位数，超基线 50%。
**不做跨用户比较。**

### C2 上下文膨胀 〔高〕（M2）

末轮/首轮 `inputTokens` 比值 + `cacheReadTokens` 占比。
⚠️ 原阈值 `cache_read < 30%` 需重新标定 —— 实测占比 **93.9%**。

### A1 / A2 资产闲置 〔中〕（M2）

已配置 MCP / 已装 skill 在 30 天内 0 调用。
数据源：cordis 配置（`profiles/*/cordis.patch.yml`）、`~/.agents/skills/`。

## 误报防护规则（一票否决）

1. **可定位** —— 每个结论必须附 locator，不可复现的结论不出
2. **死循环豁免正常重试** —— 同参数 + 同错误 + ≥3 次
3. **软信号仅 K2** —— 措辞"疑似"，不给"高"严重度
4. **单样本不出结论** —— K1 需 ≥2 会话互证
5. **禁止硬编问题** —— 未检测到异常必须在报告中显式列出
6. **处方附置信度** —— 高/中两档
7. **处方须自证** —— 必须说明它如何解决对应信号
8. **处方须可执行** —— 必须给出 YAML 片段 / 命令 / 插件入口 / 界面路径 / 指向具体动作的建议，
   并附风险、验证方式与出处；当前值已不弱于建议时撤掉该条（见 [docs/remedies.md](remedies.md)）
