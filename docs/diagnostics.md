## 分类学（5 大类 17 项）

```
C 成本类    token 过快 / 上下文膨胀 / 长会话疲劳
E 执行类    死循环 / 反复失败 / 结果过大 / 计划脱节 / 冗余重复调用（实测新增）
K 知识记忆类 跨会话失忆 / 已解决重新排查
N 环境安全类 命令反复失败 / 高风险操作 / 审批摩擦 / 重试频繁
A 资产闲置类 MCP 闲置 / skill 闲置 / 高频手动序列 / 子代理开销
```

**已移除：I 交互类**（I1 无用思考 / I2 需求反复澄清 / I3 输出不合偏好）
理由：中文启发式误报率高，且无对应的可执行处方，与"可信证据"定位冲突。

## 指标明细（已实现部分）

| 指标 | 判定 | 阈值 | 防误报 / 已知边界 |
|---|---|---|---|
| **C1** token 消耗过快 | 会话 `output / 请求数` > **主会话**单位请求 output 中位数 × 2 | `c1BaselineRatio=2`、`c1MinOutputTokens=20000`、`c1MinSessions=3` | 基线**排除子代理会话与 0 产出会话**；有绝对量下限；结论明写"产出量大不必然是浪费"（第二轮评估 F12 重写，旧版用全会话 output 总量中位数、无归一化，13 会话误报 6 个） |
| **C2** 上下文膨胀 | 末轮 input > 首轮 input × 10 且 cacheRead 占比 < 30% | `c2GrowthRatio=10`、`c2CacheShareMin=0.3`、≥8 条 assistant | 无绝对体量下限；吃缓存红利的真膨胀会漏（代码注释已自认） |
| **C3** 长会话疲劳 | 单会话 USER_MSG + ASSISTANT_MSG 计数 > 200 | `c3MaxMessages=200` | ⚠️ **不看 compaction**（注释与实际行为不一致，见评估 F19）；压缩过的长会话仍会报 |
| **E1** 死循环 | 同 `tool_name` + 同 `tool_args_hash`，配对结果**均为错误**，≥3 次 | `e1MinRepeat=3` | 参数有变化的试错不计入；幂等重试可能被误判 |
| **E2** 反复失败 | 会话工具错误率 > 30% 且调用数 ≥10 | `e2ErrorRate=0.3`、`e2MinCalls=10` | 不加权，一次环境性批量失败即触发 |
| **E3** 工具结果过大 | 单条 `tool/result` 的 `text_len` > 8192 字符，且会话内 ≥5 条 | `e3ResultChars=8192`、`e3MinCount=5`、`e3MaxFindings=3` | 只统计长度，不留正文；只列最严重的 3 个会话，其余在影响里聚合 |
| **E4** 计划执行脱节 | 取**最后一条** `todo/write`，`total>0 && done===0` 且其后 tool_call ≥5 | `e4GapCalls=5` | 只看最后一条计划；`todo_count` 结构不符则返回 null（静默不判） |
| **E5** 冗余重复调用 | 同 `tool_name` + 同 `tool_args_hash` 重复 ≥3 次且**均无错误** | `e5MinRepeat=3` | 与 E1 的边界：有一次错误就交给 E1 |
| **N1** 环境命令反复失败 | 命令类工具失败 ≥3 次（不要求同参） | `n1MinFails=3` | 与环境故障不可区分 |
| **N2** 高风险操作 | 命令执行类工具命中高危模式（`rm -rf` / `--force` / `reset --hard` / `mkfs` …） | 模式表 `dsh.mjs:98-109` | 只匹配命令文本，不匹配 write/edit 内容；`node`/`python` 也在命令类里，参数含 `--force` 即命中 |
| **N3** 权限审批摩擦 | `approval/asked` ≥5 次；报告审批次数、工具分布、等待中位、被拒数 | `n3MinAsks=5`、`n3SlowDecisionMs=60000` | 按 `id` 与 `decided` 关联；只记 id/工具名/结论，不记 `reason` 正文 |
| **N4** API 重试频繁 | `llm/retry` ≥3 次；报告失败码分布与累计退避 | `n4MinRetries=3` | 每次重试都是新的提供方请求（可能重复计费） |
| **A2** skill 闲置 | 已装 skill 在 ≥30 天窗口内 0 次触发 | `assetMinDays=30` | **判据是 `skill` 工具的 `arguments.name`**（第二轮评估 F13：旧版拿 `tool_name` 比技能目录名，永远匹配不上 → 必误报）；结论带窗口起点证据 |
| **A3** 高频手动序列 | 非通用工具的两步相邻序列 ≥5 次 | `a3MinRepeat=5` | 去镜像（`a↔b` 合并）、任一端是通用工具即排除、跨会话合并（第二轮评估 F14：旧版是相邻工具对直方图，本机误报 18 条） |
| **A4** 子代理开销 | 子代理会话 token 占比 > 40% | `a4SubagentShare=0.4` | 子代理多为正常委派；分母含空会话易越线 |

## 误报防护规则（一票否决）

1. **可定位** —— 每个结论必须附 locator，不可复现的结论不出
2. **死循环豁免正常重试** —— 同参数 + 同错误 + ≥3 次
3. **软信号不给"高"** —— 措辞"疑似"的信号不用 `高` 严重度
4. **单样本不出结论** —— 跨会话类判断需要足够窗口/样本
5. **禁止硬编问题** —— 未检测到异常必须在报告中显式列出（并带原因）
6. **处方附置信度** —— 高/中两档
7. **处方须自证** —— 必须说明它如何解决对应信号
8. **处方须可执行** —— 必须给出 YAML 片段 / 命令 / 插件入口 / 界面路径 / 指向具体动作的建议，
   并附风险、验证方式与出处；当前值已不弱于建议时撤掉该条 —— **且撤掉必须写出来**
   （报告有"已评估但未给出的处方"段，见 [docs/remedies.md](remedies.md)）
