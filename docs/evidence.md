# 证据规范与复核方法

> **本层是本项目与所有竞品的分界线。**
> 别的工具给你统计数字；本工具给你**能自己复核的证据**。

---

## 定位符格式

```
<会话文件绝对路径>#L<行号>
<会话文件绝对路径>#L<起>-L<止>      （区间）
```

示例：

```
C:/Users/you/.dsh/sessions/--C-Users-you-project--/session-32fd.../session.v4.jsonl.zstd#L101-L108
```

### 行号定义

**解码后的全局行号，1-based，跨 zstd 帧累加。**

- 不是文件内的字节偏移
- 不是 zstd 帧内行号
- 是 `decodeFrames()` 拼接后按 `\n` 切分的行序号

> 这是关键：因为文件是多帧拼接，只有"解码后全局行号"才能稳定定位。
> 前提是 `scan` 与 `show` **共用同一套切帧逻辑** —— 本项目已保证（`src/adapters/zstd-frames.mjs`）。

### 尾部空行约定

文本以 `\n` 结尾时 `split('\n')` 会产生一个尾部空串。本项目在 **scan 与 show 两侧都将其剔除**，保证行号严格一致。

---

## 复核方法

```bash
node src/cli.mjs show "<file>#L101-L108"
```

输出该区间解码后的原始记录，目标行用 `>` 标记：

```
证据位置：.../session.v4.jsonl.zstd#L101-L108
文件共 432 行 · zstd 帧 233（坏帧 0）

     99 | {"type":"tool/result", ...}
>   101 | {"type":"tool/call","data":{"name":"list_agents", ...}}
>   102 | {"type":"tool/result", ...}
```

**用户可以亲手确认结论是否成立** —— 这是建立信任的唯一路径。

---

## 设计要求

| 要求 | 实现 |
|---|---|
| 精确定位 | 区间可精确到出错的那几行 |
| 可展开 | `show` 命令，±2 行上下文 |
| 可复现 | 与 scan 共用切帧逻辑，行号一致 |
| 零外发 | 证据仅本地展示 |
| 脱敏 | 超长行截断（默认 400 字符） |
| 失败可见 | 行号越界明确报错，不静默 |

## 为什么这是护城河

诊断类工具普遍的失败原因是**不可信**：给一个数字，用户无法验证，于是不信，于是不用。

- 竞品 `kenn-io/agentsview`（6.1k★）给的是分析面板
- 竞品 `flippyhead/radar`（3★）给的是推荐列表
- **没有竞品给"可点击、可展开、可复现"的证据**

一旦用户用 `show` 亲手验证过一次结论，他对整个工具的信任就建立了。
